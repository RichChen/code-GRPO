## 审计修订 2C-2

1. **采样参数保持 T=1.0、top_p 1.0、top_k 0，不变。试点按新判定通过，接着跑全量校准。** 理由：
   - **门槛的度量选错了。** "至少出现一次格式错误的 episode 比例"会随轮数增长：每次调用的错误率是 p，n 次调用后就是 1-(1-p)^n。试点的平均轮数和用满 10 轮的比例都比 dev 高，所以这个指标被抬高了，它反映的不只是采样分布。真正反映分布的指标是每次调用的错误率，试点是 3.45%，dev 是 1.72%，在完整分布下只多了约 1.7 个百分点，很低。
   - **格式错误不会结束 episode。** 工具会返回错误信息，模型可以接着改。36 个出错的 episode 里，29 个只错了 1 次。至于"出错的 episode 很少解出"，主要是因为用满 10 轮的失败 episode 调用次数多、出错机会也多，不能说明格式错误导致了失败。
   - **GRPO 本身会压低格式错误。** 出错的 episode 大多拿 0 分，在组内是负优势，错误的那些 token 会被直接惩罚。这是 RL 要学的东西之一，不应该在采样阶段就挡掉。
   - **保持完整分布换来的是正确性。** 采样分布和 vLLM 返回的 raw logprob、训练端算出的 logp 是同一个分布，TIS 比值就是严格的重要性比值。换成 top_k 20 或降低温度，要么训练端得跟着做同样的截断和缩放，要么 TIS 修正的就不再是同一个分布。为了少一点格式错误付出这个代价，不值得。
   - **难度区间的比例是够的。** 试点里解出 1–3 次的题占 38%，按 1853 题算约 700 题，高于门槛 400。
2. **格式门槛改用每次调用的错误率。** 校准和后面所有采样都用这个口径：每次工具调用的格式错误率不超过 6%，大约是 dev 口径的 3.5 倍。"至少出错一次的 episode 比例"照常报告，不作为门槛。全量校准跑完，如果每次调用的错误率超过 6%，就停下报告。
3. **GRPO 增加两项监控和一项停止条件：**
   - 每一步记录每次调用的格式错误率和出错 episode 的比例，并在 CHECKPOINT 里报告它们在训练中的变化趋势，预期是下降。
   - 每一步记录 completion token 的平均熵。熵由训练端的 logits 计算，只在 completion 位置上算，每个 token 一个值，再取平均；不参与求导。用来发现策略坍缩。
   - 停止条件：连续 10 步的每次调用格式错误率均值超过 10%，或者平均熵低于前 5 步均值的 30%，就停下报告。
   - 本地过拟合测试只跑 30 步，熵的条件也照样检查，并报告熵的曲线。
4. **以后定新门槛，先选对度量。** 凡是会随轮数或长度增长的指标，都不能直接当门槛，要先换算成每次调用或每个 token 的口径。这一条写进计划第 1 节"规则"。
